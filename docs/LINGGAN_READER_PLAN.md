# 灵阅（LingGan Reader）开发计划

本分支用于在 Legado 3.0 基础上开发个人定制阅读器。

## 核心目标

1. 保留 Legado 原有阅读、书架、书源及本地书籍能力。
2. 增加“智能完善书籍信息”：围绕书名检索候选元数据，并由模型辅助匹配，而不是让模型凭空生成事实。
3. 计划同步的书籍字段：标准书名、作者、封面、简介、分类/标签及来源信息。
4. 增加批量整理入口，但所有覆盖操作应由用户确认。
5. 后续增加天翼云盘备份，以及多设备阅读进度同步。
6. 保持 GitHub Actions 可构建 APK。

## 实施顺序

### Phase 0：构建基线
- 保持 master 不直接修改。
- 在 `copilot/linggan-reader` 分支开发。
- 先确保现有 Android 工程及 GitHub Actions 构建链路可用。

### Phase 1：书籍元数据智能整理
- 定位 Book/BookInfo 数据模型、书籍详情编辑页面、封面加载与网络层。
- 抽象 MetadataCandidate / MetadataProvider / MetadataMatcher。
- 第一版仅处理用户主动触发的单本书籍整理。
- 搜索结果必须保留来源，低置信度时不自动覆盖。

### Phase 2：AI 辅助匹配
- 支持兼容 OpenAI 风格的模型配置。
- AI 仅对搜索得到的候选资料进行标准化、去重和候选匹配。
- API Key 不写入仓库，不进入普通明文备份。
- AI 不作为封面、作者、简介等事实信息的唯一来源。

### Phase 3：批量整理
- 增加书架批量扫描。
- 只处理缺失字段，除非用户明确允许覆盖。
- 提供整理前后的差异预览。

### Phase 4：天翼云盘
- 将云盘实现隔离为独立同步模块。
- 完整备份与阅读进度同步分离。
- 阅读进度采用轻量数据同步并考虑多设备冲突。
- 凭据不得写入 Git 仓库。

## 安全和兼容原则

- 所有外部网络数据按不可信输入处理。
- 不在源码或 GitHub Actions 文件中硬编码用户密码、云盘凭据或 AI API Key。
- 修改数据库结构时提供明确迁移策略，避免破坏现有书架数据。
- 尽量减少对 Legado 核心阅读逻辑的侵入，方便后续跟随上游更新。
- 保留项目原有 GPL-3.0 许可证及版权信息。
